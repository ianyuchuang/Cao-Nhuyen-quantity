# 工項進度登記網站

工程師用手機依「工項 → 樓層 → 房間 → 代號細項」登記完成百分比；結果寫進 Google 試算表「工項進度登記」，每日完成量寫到「網站每日數量」，由內業對照正式版決定要不要填進正式版。

- **網頁**：`web/`，純靜態，放 GitHub Pages（公開）。網頁裡**沒有任何數量、單價**，登入後才從試算表取資料。
- **API**：`apps-script/`，綁定試算表「工項進度登記」的 Apps Script，部署成網頁應用程式。
- **正式版「高軟每日施工內容(正式版)」只讀**：程式只從它讀取（同步主表、算期初），任何情況都不寫入。

```
進度登記網站/
├─ apps-script/        貼到試算表的 Apps Script（7 個 .gs＋appsscript.json）
│   ├─ Config.gs      設定、欄位位置、共用工具
│   ├─ Auth.gs        Google ID token 驗證、共用名單權限
│   ├─ Api.gs         doGet / doPost：bootstrap、submit、material、history、recalc
│   ├─ Data.gs        讀寫「位置」「目前進度」「進料」等
│   ├─ Recalc.gs      重算「網站每日數量」、設定期初
│   ├─ Sync.gs        從正式版同步主表、對齊「網站每日數量」
│   ├─ Menu.gs        試算表選單、每日觸發
│   └─ appsscript.json
├─ tests/gas-test.js   Apps Script 本機單元測試（模擬試算表）
└─ web/                放到 GitHub Pages 的網頁
    ├─ index.html  app.js  style.css
    ├─ config.js      ← 部署後填 API 網址與 OAuth 用戶端 ID
    └─ demo.js        示範模式的假資料（不連線）
```

## 部署步驟（第一次，約 30 分鐘）

### 1. 建立 Google Cloud 的 OAuth 用戶端 ID

1. 用你的 Google 帳號開 <https://console.cloud.google.com/>，左上角專案選單 →「新增專案」，名稱例如「工項進度登記」。
2. 左側選單「API 和服務」→「OAuth 同意畫面」（新版叫「Google Auth Platform」）→ 開始設定：
   - 應用程式名稱：工項進度登記；使用者支援電子郵件：你的信箱。
   - 目標對象：**外部**。
   - 聯絡資訊：你的信箱 → 建立。
   - 「目標對象」頁把發布狀態改為**正式版（發布應用程式）**。只用登入的基本資料（email、名稱），**不需要 Google 審核**；若維持「測試」，只有加進測試使用者名單的帳號能登入。
3. 「用戶端」（或「憑證」）→「建立用戶端」→ 類型選**網頁應用程式**：
   - 名稱：進度登記網站。
   - **已授權的 JavaScript 來源**：填 GitHub Pages 網址的網域，例如 `https://你的帳號.github.io`（只要網域，不含路徑、結尾不加 `/`）。不要把 `http://localhost` 加進正式用戶端（本機佔用該埠的程式就能拿到本站的登入憑證）；要在自己電腦測真實登入，另建一個開發用的用戶端 ID。
   - 已授權的重新導向 URI：**不用填**。
4. 建立後複製「用戶端 ID」（`…….apps.googleusercontent.com`）。這個值不是機密，會放在公開網頁上。

### 2. 把 Apps Script 貼進試算表

1. 開試算表「工項進度登記」→「擴充功能」→「Apps Script」。
2. 左側齒輪「專案設定」→ 勾選「在編輯器中顯示『appsscript.json』資訊清單檔案」。
3. 回「編輯器」：
   - 把預設的 `程式碼.gs` 刪掉（或改名）。
   - 依序按「＋」→「指令碼」，建立 `Config`、`Auth`、`Api`、`Data`、`Recalc`、`Sync`、`Menu` 七個檔案，各貼上 `apps-script/` 同名檔的內容。
   - 打開 `appsscript.json`，整個換成 `apps-script/appsscript.json` 的內容。
   - 按「儲存」。
4. 上方函式選單選 `onOpen` →「執行」→ 會跳出授權：選你的帳號 →「進階」→「前往（不安全）」→「允許」。會要求的權限：
   - 查看及管理試算表（讀寫本試算表、讀正式版、查本試算表的共用名單）
   - 連線到外部服務（向 Google 驗證登入憑證）
   - 管理觸發條件（每日同步）、在試算表顯示選單

   （「不安全」是因為這是你自己寫的程式、沒經過 Google 審核，屬正常。）
5. 「部署」→「新增部署作業」→ 齒輪選「網頁應用程式」：
   - 說明：進度登記 API
   - **執行身分：我**
   - **具有存取權的使用者：任何人**（實際權限由試算表共用名單把關；「任何人」才能讓 GitHub Pages 的網頁呼叫）
   - 按「部署」，複製「網頁應用程式網址」（`https://script.google.com/macros/s/……/exec`）。

> 之後改了程式：「部署」→「管理部署作業」→ 鉛筆 →「版本：新版本」→「部署」。網址不變。

**也可以用 clasp（指令列）**：
```bash
npm install -g @google/clasp
```
```bash
clasp login
```
在 `apps-script/` 建 `.clasp.json`，內容 `{"scriptId":"<Apps Script 專案設定裡的指令碼 ID>","rootDir":"."}`，再執行：
```bash
clasp push
```
（clasp 會把 `.gs` 上傳；部署仍照上面第 5 步在網頁操作，或用 `clasp deploy`。）

### 3. 填「設定」表

在試算表「設定」工作表：

| 項目 | 值 |
|---|---|
| OAuth 用戶端 ID | 第 1 步複製的用戶端 ID（**一定要填**，API 用它驗證登入憑證） |
| 網站網址 | GitHub Pages 網址（備查） |
| 上線日 | 網站開始負責每日數量的那一天，例如 `2026-12-01`（填了才會寫「網站每日數量」） |
| 權限來源 | 新增這一列（選填）：`試算表共用`（預設）或 `人員表`，見第 5 步 |

### 4. 填網頁設定並放上 GitHub Pages

1. 編輯 `web/config.js`：
   ```js
   window.APP_CONFIG = {
     API_URL: 'https://script.google.com/macros/s/……/exec',
     CLIENT_ID: '…….apps.googleusercontent.com'
   };
   ```
2. 在 GitHub 新建一個倉庫（例如 `progress`），**只放 `web/` 資料夾裡的檔案**（index.html、app.js、style.css、config.js、demo.js）。
   **不要**把 `D:\分層數量` 整個資料夾推上去：那裡有建築圖、數量表與含單價的 CSV，GitHub Pages 一律公開。
3. 倉庫「Settings」→「Pages」→ Source 選「Deploy from a branch」→ Branch 選 `main`、資料夾 `/ (root)` → Save。約 1 分鐘後網址會是 `https://你的帳號.github.io/progress/`。
4. 確認第 1 步「已授權的 JavaScript 來源」有填 `https://你的帳號.github.io`。

### 5. 加人

有兩種做法，由「設定」表的「權限來源」決定：

**A. 試算表共用（預設，照規劃稿）**：在試算表按「共用」加入對方的 Google 帳號（個人 Gmail 也可以）：

| 共用身分 | 網站上 | 試算表 |
|---|---|---|
| 檢視者（或加註者） | 登入、查看、登記所有工項的進度與進料、看所有人的修改紀錄 | 只能看 |
| 編輯者 | 同上，另可「全部重算」 | 可直接改 |
| 未共用 | 登入後顯示「請向管理者申請權限」 | — |

- 權限快取 10 分鐘。移除某人後要立即生效：試算表選單「進度登記」→「清除權限快取」。
- 「人員」表可填 Google 帳號與顯示名稱，網站與「目前進度」會顯示名稱（沒填就用 Google 名稱）。
- 不要把試算表設成「知道連結的任何人」，那樣個別帳號不會出現在共用名單，會被擋。
- ⚠ 檢視者可以直接打開試算表，而主表「施工-實際進度」是正式版鏡像，**含單價、複價**。如果不想讓工地人員看到金額，請用 B。

**B. 人員表（建議，資安審查建議）**：「設定」表加一列 `權限來源`＝`人員表`。
- 工程師**不必共用試算表**。工程師第一次用 Google 帳號登入網站時，系統會自動把帳號與 Google 名稱寫進「人員」表（A Google 帳號、B 顯示名稱、C 備註、D 核准），D 欄「核准」＝未勾選，網站顯示「已送出使用申請」。
- 管理者**勾選**該列 D 欄「核准」即可使用；工程師重新整理網頁（或按「管理者已核准，重新檢查」）就能進入，不必重新登入或清瀏覽器資料。
  - 只有勾選（TRUE）才可用；未勾選、空白或任何文字都不可用（白名單）。停用某人＝取消勾選，原因可寫在 C 欄備註。程式依第 1 列表頭「核准」找欄位，所以欄位前後調整不會認錯。
  - 在試算表介面編輯「人員」或「設定」表時，`onEdit` 會立即清除權限快取，所以勾選／取消勾選立即生效；用 API 或程式改人員表不會觸發，最慢 30 秒（`PEOPLE_TTL`）生效。
  - 核准時請以 **email（A 欄）** 為準，B 欄名稱是對方自訂的 Google 名稱，可能冒用同事姓名。
  - 除錯：Apps Script 編輯器執行 `aclCacheStatus` 可看權限快取是否存在、`warmAclCache` 可建立快取（2026-11-19 實測：勾選或取消勾選後快取立即清空）。
- 也可以直接在「人員」表手動填帳號（A 欄）、顯示名稱（B 欄），並勾選 D 欄。
- 不分負責工項：核准的人都能登記、查看所有工項，修改紀錄看得到所有人的登記（登記人顯示人員表名稱）。
- 試算表的編輯者（主任、內業）仍是網站的編輯者。
- 這樣工程師完全碰不到試算表，看不到任何金額。

### 6. 上線

1. 「設定」表填好**上線日**。
2. 試算表選單「進度登記」→「從正式版同步主表」（第一次確認能讀正式版）。
3. 「進度登記」→「**設定期初**」：以上線日前正式版的使用數量算期初%（= 使用數量 ÷ 圖面合計，上限 100%），平均設到每個位置，並把期初數量寫到「網站每日數量」J 欄。完成後會列出「使用數量超過圖面合計」的代號。
4. 「進度登記」→「安裝每日同步觸發（每天 02:00）」：每天從正式版同步主表並全部重算。
5. 用手機開 GitHub Pages 網址，用 Google 帳號登入試一筆。

## 完成量算法（2026-11-19 起：進料以 50% 計）

- 每個代號（層級）的完成量 ＝ 圖面合計 × 50% × 進料比例 ＋ Σ（各位置圖面數量 × 50% × 該位置施作完成%）。
  - 進料比例 ＝ min(進料累計 ÷ 圖面合計, 1)，進料累計來自「進料」表（代號層整批填的到貨數量，含期初）。
  - 網站上各位置填的完成% 只代表「施作」那一半；一間房施作 100% 且進料完成＝100%。
  - 門窗的框 60%／扇 40% 只分施作那一半；進料仍在代號層整批填。全部工項一律以 50% 計。
- 「網站每日數量」：累計(D) 依上式計算（進料與施作都取日期 ≤ D 的資料），當日＝累計(D)−累計(前一天)，所以進料到貨那天會出現在當天數量。
- 「分層進度」Z 欄＝進料比例；「目前進度」J 欄完成量＝圖面數量 ×（50% × 施作% ＋ 50% × 該代號進料比例），所以「分層進度」的完成量、完成% 與上式一致。
- 期初（上線日前）：期初總% ＝ 正式版使用數量 ÷ 圖面合計（上限 100%），拆成
  - 進料期初比例 ＝ min(1, 期初總% ÷ 50%)（例外：貼面磚全部、A梯 a/b 型、B梯 c/d 型欄杆＝1，見 `Config.gs` 的 `OPENING_MAT_FULL_*`）→ 寫進「進料」表；
  - 施作期初% ＝ max(0, (期初總% − 50%) ÷ 50%) → 平均設到各位置，寫進「進度紀錄」。
  - 兩者日期都記上線日前一天、登記人「系統（期初推估）」；重設期初會先刪掉舊的期初列。
- 上線後（第 13 版起）：每次從正式版同步主表（每日 02:00 的 `nightlyJob`，或選單「從正式版同步主表」），同步完會檢查每個網站管理的代號：
  - 正式版使用數量（主表 G 欄）÷ 圖面合計 ≥ 50%，且「進料」累計 < 圖面合計 → 在「進料」表補一筆，數量＝圖面合計 − 目前進料累計，日期＝當天，登記人「系統（正式版≥50%）」，備註寫當時的正式版使用數量與比例；補完立即重算該代號。
  - 只補不減：正式版之後降回 50% 以下不扣回。已補滿就不再補，所以同一天重跑或手動重跑不會重複。正式版超過圖面也只補到圖面合計。
  - 主表 G 欄表頭不是「使用數量」（正式版欄位變動）時整個略過，避免讀錯欄。
  - 工程師登記的進料登記人一律是驗證過的 email，無法偽造成「系統（正式版≥50%）」。
  - 2026-11-20 第一次實跑：正式版 ≥ 50% 的 97 個代號進料都已在期初補滿，沒有需要補的；最接近門檻的有 F3（49.36%）、W12（49.64%）、W5（49.16%）、玻璃D3F（49.05%）等。
  - 「網站每日數量」J 欄＝網站推估的上線前累計，所以 G 網站累計＝目前網站完成量；例外代號（例如 A梯 a 型正式版已用 0、網站 50%）與超過圖面的代號，差額會出現在 I 欄，屬預期。

## 運作方式

- **登入**：網頁用 Google 登入按鈕取得 ID token，每個請求都帶著；Apps Script 向 Google 驗證 token 是發給本網站（aud＝「設定」表的用戶端 ID）、未過期、email 已驗證，再查 email 是否在本試算表的共用名單。token 約 1 小時過期，過期時網頁會請你再登入，未送出的資料不會遺失。
- **登記**：樓層、房間、代號三層都可填（門窗也是「樓層 → 房間 → 代號 → 每一樘」，見下方「門窗依房號」）；上層覆蓋底下前，如果底下已有不同的值會先提示。完成% 比上次低要填原因。門窗每樘分框 60%／扇 40%（窗：窗框／玻璃及五金；捲門：導軌及捲軸箱／門片及電動機）。比例分配的數量與進料在「代號層」。
- **寫入**：每筆登記寫「進度紀錄」（只新增，含舊值、原因、登記人、時間、UUID），並更新「目前進度」的完成%、框、扇、日期、登記人（**不寫 J 欄完成量公式**）。補登較早日期只進紀錄與每日數量，不覆蓋較新的目前進度。
- **網站每日數量**：寫入後重算該層級上線日之後每一天：累計(D) = 每個位置取施工日期 ≤ D 的最新一筆 × 圖面數量；當日 = 累計(D) − 累計(前一天)。只寫 K 欄以後、上線日以後的日期欄；E、G、H、I 是公式不碰；J 是期初。
- **衝突**：送出時帶「看到的舊值」，和試算表不同就不寫入，網頁顯示「被別人改過」，可選「採用目前值」或「以我的為準重送」。
- **離線**：送不出去的留在手機（localStorage），恢復連線或每 30 秒自動依 UUID 重送，不會重複寫入。
- **同步主表**：把正式版「施工-實際進度 (修訂2版)」複製成暫存工作表取格式，數值則讀正式版算好的值寫入本表「施工-實際進度」（不帶公式；正式版的公式參照它自己的「修訂1版」等工作表，帶過來會變 #REF!），刪暫存表。正式版插入或刪除列時，「網站每日數量」依層級重排，期初與逐日數量跟著層級走。

## 資安措施

已請 Fable 5.2 審查三次並修正（2026-11-19 第二次審查的 1～4 項在第 10 版、5～6 項在第 11～12 版修正；2026-11-20 第三次審查中度 2 項在第 14 版、低度 8 項在第 15～16 版與網頁修正）：
- **登入**（第 14 版起）：ID token 在 Apps Script 本機驗證，不呼叫 tokeninfo——先檢查宣告（`alg`＝RS256、aud＝「設定」表的 OAuth 用戶端 ID、簽發者是 Google、未過期、email 已驗證），再用 Google 公開金鑰（JWKS，`https://www.googleapis.com/oauth2/v3/certs`）驗 RS256 簽章（BigInt 模冪＋PKCS#1 v1.5 SHA-256）。
  - 公開金鑰快取到 Cache-Control 期限（最多 6 小時）；憑證帶了不認得的 `kid`（Google 換金鑰）時重抓一次，但最多每 10 分鐘一次。
  - 偽造或竄改的憑證完全不產生對外連線，所以不再需要全域次數上限，也就無法被拿來擋住所有人登入（第三次審查第 2 項）。
  - 驗證成功的快取到憑證到期。GET 不接受 token（只做健康檢查）。
  - 編輯器執行 `jwtSelfTest` 可確認本機驗章在 Apps Script 上可用（2026-11-20：讀到 Google 公開金鑰 2 把，測試向量驗證 true、竄改後 false）。
- **正式版欄位檢查**（第 14 版起，第三次審查第 1 項）：同步時先檢查正式版第 3 列表頭（A 層級、B 項目、C 單位、D 單價、E 數量、F 複價、G 使用數量、K 起為日期，`CFG.OFFICIAL_HEADERS`），不符就停止同步、主表不改（每日同步會失敗並留下錯誤紀錄）。網站回傳「正式版使用數量」前也確認主表 G3＝「使用數量」，不符就不回傳，避免正式版插欄後把複價送到網頁。
- **權限**：每個請求都重查名單；人員表只認「核准」勾選 TRUE（白名單）；全部重算只限編輯者；其餘登記、查看、修改紀錄所有核准的人都一樣。
- **公式注入**：原因、備註、顯示名稱、email 等文字寫進儲存格前，開頭是 `= + - @`（含全形 `＝＋－＠`，`FORMULA_START`）會加 `'` 存成文字並限長；填寫層級用白名單格式。試算表讀回時會吃掉這個 `'`，所以所有寫入（含「目前進度」整欄重寫、從進度紀錄重建、同步主表、同步重排「網站每日數量」的表頭日期與期初／逐日值）都再套一次 `protectRows_`；重設期初刪舊期初列改用 `deleteRows`，不再把整張表讀出再寫回。
- **UUID**（第 15 版起）：只收 8-4-4-4-12 十六進位格式（`uuidOf_`，網頁用 `crypto.randomUUID` 產生），一律存小寫；`00000001`、`2026-11-19` 這類會被試算表轉成數字或日期、讓去重失效的值直接拒絕。
- **濫用**：請求上限 1 MB、一次最多 3000 筆、每個帳號每分鐘 60 次（未授權者也先限流，再自動加入人員表；計數的讀＋寫包在鎖裡，並行請求也不會超過，`withRateLock_`：document lock，取不到改 user lock，都不能用才照舊計數；健康檢查 GET 會回報 `lock`，2026-11-20 實測為 `document`）；待核准最多 200 筆（只算 A 欄有帳號的列，預先拉好的空白勾選框不算；新申請填進第一個空白列），名額滿時回「申請名額已滿，請直接聯絡管理者」，同一帳號 10 分鐘內不再搶鎖；UUID 去重；查表用無原型物件。
- **上線日必填**（第 15 版起）：「設定」表的上線日空白或格式錯誤時，進度與進料登記一律拒絕（回 `config`，網頁把資料留在手機、修好後自動重送），不會變成可以補登任何過去日期。
- **登入失敗不寫快取**：格式錯誤或驗不過的憑證不寫任何快取（第 14 版起已沒有負快取），未登入者無法大量寫入快取擠掉其他項目。
- **進料登記**：日期不早於上線日、不晚於今天；單筆不超過圖面合計 2 倍；負數（退料、更正）必須寫備註；登記後累計不能小於 0；每個帳號每分鐘最多 10 筆（`MAT_RATE_PER_MIN`，第 15 版起在登記鎖內計數）。網頁送出前也做同樣檢查。
- **資料**：API 不讀主表，回傳只有數量、百分比與名稱，沒有單價、複價；錯誤訊息不含內部細節。
- **網頁**：CSP（只允許本站、Google 登入與本部署的 Apps Script 路徑 `script.google.com/macros/s/<部署 ID>/`；換部署 ID 時 `web/index.html` 的 CSP 要跟 `web/config.js` 一起改，`tests/web-test.js` 會檢查）、離線佇列從 localStorage 讀回時檢查格式（`web/outbox.js`，格式不對的批次丟掉並提示，不會讓畫面卡住）、no-referrer、禁止被其他網站嵌入；所有畫面文字都跳脫；Google 登入不自動選帳號（共用手機）；登出時提醒還有沒送出的資料。
- **權限範圍**：Apps Script 只要試算表、外部連線、觸發器、選單；不要雲端硬碟權限。
- **正式版（Google 權限保證唯讀）**：Apps Script 的權限範圍只有 `spreadsheets.currentonly`（只能改綁定的這份試算表）＋ `spreadsheets.readonly`（其他試算表只能讀），沒有「編輯所有試算表」；程式就算寫錯也改不到正式版。同步用 Sheets API（進階服務）的 `spreadsheets.get`／`values.get` 讀正式版數值；主表格式保留不動（正式版新增列時新列沿用上一列格式，正式版改底色、合併等不會同步過來）。編輯器執行 `officialAccessCheck` 可確認目前授權的範圍。
  - 若日後看到授權仍含「查看、編輯、建立及刪除您的所有 Google 試算表檔案」，是舊授權累積：到 Google 帳戶「第三方存取權」移除「工項進度登記 API」，再到 Apps Script 執行任一函式重新授權（2026-11-19 已做過一次）。
- 建議：GitHub Pages 用獨立的 GitHub 帳號或組織（`帳號.github.io` 底下所有專案頁同源，共享 sessionStorage 等）。

## 疑難排解

| 狀況 | 處理 |
|---|---|
| 登入按鈕出現「origin_mismatch」或沒出現 | OAuth 用戶端的「已授權的 JavaScript 來源」沒有填網頁的網域 |
| 登入後「登入憑證不是發給本網站的」 | 「設定」表的 OAuth 用戶端 ID 與 `config.js` 不一致 |
| 「尚未核准」「請向管理者申請權限」 | 人員表模式：請管理者勾選「人員」表 D 欄「核准」後重新整理網頁。試算表共用模式：名單快取 10 分鐘，要立即生效按「清除權限快取」 |
| 手動刪改了「進度紀錄」 | 選單「從進度紀錄重建目前進度」 |
| 「請求太頻繁」 | 每個帳號每分鐘上限 60 次，稍等會自動重送 |
| 網站每日數量沒有值 | 「設定」表沒填上線日，或還沒「設定期初」；可按「全部重算」 |
| 改了「位置」的圖面數量 | 選單「清除位置快取」再「全部重算」 |
| 改程式後網站沒變 | Apps Script 要「管理部署作業 → 新版本」；GitHub Pages 要等 1～2 分鐘並重新整理 |
