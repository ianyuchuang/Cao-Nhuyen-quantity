工項進度登記網站

工程師依「工項 → 樓層 → 房間 → 代號細項」找到要登記的位置，看到該代號在這個房間的面積，填完成百分比；也可以一次填整層或整間。系統以圖面數量加權彙總，直接換算成每日施工內容表的使用數量。

1資料規模

工項代號房間／組登記筆數單位施作細項資料來源

「登記筆數」是最小的登記單位：一般工項是「房間 × 代號」，門窗是「每一樘」，比例分配的數量（欄杆樓梯扶手、防水筏基、油漆樑等）合併成每個代號一筆「不分樓層」。同一房間同一代號在計算式有多列時合併成一筆。

3計算規則

完成量與彙總

位置完成量 = 圖面數量 × 完成% 單樘完成% = 框 60% × 框完成 + 扇 40% × 扇完成 房間完成% = Σ位置完成量 ÷ Σ圖面數量（同單位才合併） 代號完成% = 該代號 Σ完成量 ÷ 該代號圖面合計 累計(D) = 每個位置取「施工日期 ≤ D 的最新一筆」 當日完成量 = 累計(D) − 累計(D−1)
  • 登記直接生效，不日結；任何日期都可以補登或更正，每筆都留修改紀錄。
  • 完成% 比上次低時要填原因；當日完成量可以是負數，照實匯出。
  • 匯出時依當下資料重算；已匯出的日子若被補登，匯出檔會不同，所以匯出檔標記產生時間。
  • 數量改版：已登記的 % 保留，完成量依新數量重算。
  • 兩人同時登記同一位置：送出時帶「看到的舊值」，與伺服器不同就提示確認。

對接每日施工內容表

主表逐日欄(層級, D) = 當日圖面完成量（D ≥ 上線日） 期初% = 上線前使用數量 ÷ 圖面合計（上限 100%）
  • 依你的決定直接用圖面完成量匯出。CSV 的執行率會超過或達不到 100%（例如 C6 完工時 146%）。
  • 期初要除以圖面合計（不是合約），上線當天的累計才會等於 CSV 已用數量。例如 C6 已用 500 m²，期初 = 500 ÷ 5,225.6 = 9.6%，平均設到每個房間並標示「期初推估」，工程師再用版面 C 更正。
  • 進料記在 material，與施作完成% 分開；匯出時怎麼用見待確認第 1 題。
  • W6 已併入 W5，網站只寫 W5 那一列，W6 照舊手填（或另定拆分比例）。
  • 主表日期欄改成真正的日期（顯示仍是 m/d），CSV 裡 4/8 出現兩次（2026、2027）的問題就解決了。

4五個版面設計

五個版面都可以操作，工項、樓層、房間、代號、面積與門窗每一樘都是真實資料。完成百分比與進料數量是示範用的隨機值。五個版面共用同一份資料，在任一版面修改，其他版面會同步。試試看：版面 A 選「門窗」看逐樘的門框、門扇；在任一版面按「整層設為」看覆蓋提示。

示範資料只存在這個頁面，重新整理會回到預設值。

7.1主機與資料庫

已決定：網頁放 GitHub Pages，資料存在試算表「工項進度登記」，用 Apps Script 當 API；登入用 Google 帳號，誰能用由你在試算表的「共用」設定決定。

工程師用 Google 帳號登入→GitHub Pages 網頁取得 Google 身分憑證→Apps Script 驗證憑證，查此人是否在試算表共用名單↔試算表「工項進度登記」
你在試算表的共用設定網站上的權限能不能直接改試算表
檢視者登入、查看、登記進度與進料不能（只能透過網站寫入，資料最乾淨）
編輯者同上，另可按「全部重算」、看全部人員紀錄可以（給主任、內業）
未共用登入後顯示「請向管理者申請權限」—

新增人員：在試算表按「共用」加入對方的 Google 帳號即可，不用另外建帳號或密碼；移除共用就立即失去權限。工程師用的 Google 帳號可以是個人 Gmail。

為什麼不直接用 Apps Script 網頁（不經 GitHub Pages）

Apps Script 自己也能出網頁，設定「以使用者身分執行」就會自動要求 Google 登入。但每位工程師都必須是試算表編輯者（可以直接改表），而且手機瀏覽器同時登入多個 Google 帳號時常出現「目前無法開啟檔案」，現場不好排除。所以維持 GitHub Pages ＋ Google 登入按鈕。

一次性設定（約 15 分鐘）

  • Google Cloud 建一個專案與「OAuth 用戶端 ID（網頁應用程式）」，允許的來源填 GitHub Pages 網址；只用 email 等基本權限，不需 Google 審核。
  • 試算表時區改為「(GMT+08:00) 台北」，目前是 GMT，日期會差一天。
  • Apps Script 部署為網頁應用程式：「以我的身分執行」「任何人」可存取（實際權限由共用名單把關）。

Apps Script API

動作說明
每個請求附 Google 身分憑證（ID token）；Apps Script 向 Google 驗證憑證、確認 email 在試算表的檢視者或編輯者名單，結果快取 10 分鐘

注意事項

  • 數量不放進 GitHub Pages：Pages 網頁一律公開（私有倉庫也一樣），網頁只放程式，數量與進度都在登入後才從試算表取。
  • 跨網域：POST 用 Content-Type: text/plain 避開 CORS 預檢；Apps Script 的回應會轉址到 googleusercontent.com，fetch 會自動跟隨。
  • 寫入身分：Apps Script 以你的身分寫入，「進度紀錄」的登記人欄記下驗證過的 email；編輯者若直接改表，Google 版本記錄也查得到是誰。
  • 速度：每次寫入約 1～3 秒。網頁先顯示結果、背景送出；失敗的留在手機的離線佇列，連線後用 UUID 重送，不會重複。
  • 容量與配額：試算表上限 1,000 萬格；進度紀錄每年估 3 萬筆 × 12 欄約 36 萬格。Apps Script 同時執行約 30 個，十幾位工程師足夠。
  • 多人同時寫：LockService 讓寫入排隊；舊值與試算表不同的筆數退回網頁，讓工程師確認後再送。
  • 備份：每週觸發器複製一份試算表到雲端硬碟資料夾，另有版本記錄可還原。
  • 匯入：extract.py 加一個輸出，產生代號、房間、位置、期初各工作表的資料，數量改版時重跑並標記版本。

  • 主表只從正式版讀取同步；正式版插入或刪除列時，同步程式也會重排「網站每日數量」的列，保持對齊。
